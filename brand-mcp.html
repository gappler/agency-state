The practice

Serving your brand to AI tools

How MCP serves each AI tool the part of the brand it needs.

The job

MCP gives the source a serving layer. The brand stays in one governed place. Tools ask for the part they need: voice, vocabulary, claims, product facts, visual rules, review criteria, or the full platform.

serving layer: source stays governed tools ask for the right slice responses stay scoped to the task checks use the same source drafts use updates happen in one place

Source and server

The source and the server are different things.

The source is the approved brand material: structured files, provenance, rules, decisions, and review notes. The server reads that source and exposes useful answers to the tools doing the work.

That split keeps the brand maintainable. The team can govern the source as brand material. The MCP server can focus on access, caching, tool names, response shapes, and connections.

pattern: brand source: - maintained by the team - reviewed and versioned - structured for drafting and checks MCP server: - reads the source - exposes useful tools - returns scoped answers - connects to agents and workflows

What tools ask for

A useful brand server is designed around the work. A writing task may need the voice and never-say list. A review task may need claims, proof, and product facts. A page build may need visual rules. A workflow may need the decision owner so it knows who should review an exception.

The useful pattern is scoped serving: the relevant source appears at the moment it is needed. Connecting a server makes its tools available, but it doesn't make an agent ask for the right part. The workflow has to say what to request and when.

requests by task: writing: voice, never-say list review: claims, proof, product facts page build: visual rules exception: the decision owner

How it works here

The Agency State version is small. The brand source lives in the brand repo. The MCP server reads from that source and returns whole sections of the platform and the visual identity as tools.

Claude Code and Codex call those tools while writing or reviewing site copy. The important part is the shared connection: the same source supports drafting and checking.

The server keeps what it reads for about 60 seconds. If it can't reach the source, it answers from a bundled copy, which can be older. A shared connection makes the latest version available; it doesn't guarantee every answer has it.

Agency State example: source: agency-state-brand server: agency-state-brand-mcp host: Railway clients: Claude Code, Codex current tools: get_identity get_positioning get_audience get_brand_voice get_vocabulary get_never_say get_proof get_boundaries get_competencies get_full_platform get_visual_identity

More specific requests

The more specific version starts with codification. Agency State's BrandBuilder turns the brand material into structured brand files, shows gaps and conflicts, and gives the team something to review. Once that source is approved, BrandBuilder's own server can serve it into production.

At that point the tools can become more specific. They can return voice guidance, including channel guidance, the facts for one product, the approved claims for one product with their conditions, visual rules, or the owner of one class of decision. Agency State's own brand hasn't moved to that format yet.

BrandBuilder requests: get_voice: voice guidance get_products: facts for one product or line get_claims: approved claims with their conditions get_decision_owner: who decides a class of question get_brand_status: approval status and source revisions
the pattern: assess: score the brand inventory codify: build the reviewed source serve: expose the source to agents and workflows produce: draft and adapt from the source check: compare output to the source route: send judgment calls to the decision owner update: return approved corrections to the source

Why it matters

Without a serving layer, brand context scatters. One copy lives in a prompt. Another lives in a custom assistant. Another sits in an agency deck. Each copy can age differently.

Serving the source keeps the work connected. The system can draft from the same material it checks against. People can update one source while automations and agents use the brand without each becoming a separate brand repository.

MCP handles the connection. The brand work is deciding what the source contains, how it should be served, and who decides when the source has no answer.
