The practice

Serving the brand source

MCP is one way to give AI tools the right part of the brand while the work is happening.

The job

A codified brand is useful only when the tools doing the work can reach it. The source can be well structured, reviewed, and owned, but if every agent gets a pasted copy, a stale upload, or a rewritten summary, the brand starts to drift again.

MCP gives the source a serving layer. The brand stays in one governed place. Tools ask for the part they need: voice, vocabulary, claims, product facts, visual rules, review criteria, or the full platform.

serving layer: source stays governed tools ask for the right slice responses stay scoped to the task checks use the same source drafts use updates happen in one place

Source and server

The source and the server are different things.

The source is the approved brand material: structured files, provenance, rules, decisions, and review notes. The server reads that source and exposes useful answers to the tools doing the work.

That split keeps the brand maintainable. The team can govern the source as brand material. The MCP server can focus on access, caching, tool names, response shapes, and connections.

pattern: brand source: - owned by the team - reviewed and versioned - structured for drafting and checks MCP server: - reads the source - exposes useful tools - returns scoped answers - connects to agents and workflows

What tools ask for

A useful brand server is designed around the work. A writing task may need the voice and never-say list. A review task may need claims, proof, and product facts. A page build may need visual rules. A workflow may need decision rights so it knows who should review an exception.

The useful pattern is scoped serving: the relevant source appears at the moment it is needed.

example requests: get_voice(channel: "email") get_never_say() get_product_facts(product: "Yowie 35QT") get_claim_rules(topic: "ice retention") get_visual_rules(surface: "landing page") get_review_route(issue: "legal exception")

How it works here

The Agency State version is small, but it proves the pattern. The brand source lives in the brand repo. The MCP server reads from that source and exposes slices of the platform and visual identity as tools.

Claude Code can call those tools while writing or reviewing site copy. Workflows can call the same source. The important part is the shared connection: the same source supports drafting and checking.

Agency State example: source: agency-state-brand server: agency-state-brand-mcp host: Railway clients: Claude Code, n8n current tools: get_identity get_positioning get_audience get_brand_voice get_vocabulary get_never_say get_proof get_boundaries get_competencies get_full_platform get_visual_identity

The stronger version

For client work, the stronger pattern starts with codification. BrandBuilder reads the existing material, builds the baseline source, shows gaps and conflicts, and gives the team something to review. Once that source is approved, MCP can serve it into production.

At that point the tools can become more specific. They can return the voice for one channel, the facts for one product, the rules for one claim, the visual constraints for one surface, or the review route for one class of question.

client pattern: assess: score the brand inventory codify: build the reviewed source serve: expose the source to agents and workflows produce: draft and adapt from the source check: compare output to the source route: send judgment calls to the owner update: return settled corrections to the source

Why it matters

Without a serving layer, brand context scatters. One copy lives in a prompt. Another lives in a custom assistant. Another sits in an agency deck. Each copy can age differently.

Serving the source keeps the work connected. The system can draft from the same material it checks against. People can update one source while automations and agents use the brand without each becoming a separate brand repository.

MCP is plumbing. The brand work is deciding what the source contains, how it should be served, and who owns the decisions when the source runs out.
