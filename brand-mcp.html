Serving your brand to AI tools

How MCP serves each AI tool the part of the brand it needs.

The job

MCP is an open standard for connecting AI tools to outside data. For a brand, MCP serves marketing tools the brand material they need for the task, from voice guidance to the full platform.

serving layer: source stays governed tools ask for the right slice responses stay scoped to the task checks use the same source drafts use updates happen in one place

Source and server

The source and the server are different things.

The source is approved brand material, including structured files, provenance, rules, decisions, and review notes. The server reads it and answers requests from tools.

The team governs the brand material. The server handles access, caching, tool names, response formats, and connections.

pattern: brand source: - maintained by the team - reviewed and versioned - structured for drafting and checks MCP server: - reads the source - exposes useful tools - returns scoped answers - connects to agents and workflows

What tools ask for

Writing, review, and page builds each call for different brand material. A workflow handling an exception can request the decision owner.

Connecting a server makes its tools available, but an agent still needs instructions to request the right part. The workflow says what to request and when.

requests by task: writing: voice, never-say list review: claims, proof, product facts page build: visual rules exception: the decision owner

Serving Agency State's brand

My brand is codified as structured brand files, reviewed by me on October 27, 2026, and served through an MCP server. A writing tool can request the phrases I rule out and how strictly each is treated.

request: get_never_say() response excerpts: - word: 10x your output severity: hard - word: unlock severity: hard - word: AI-powered severity: hard

A request for the claims decision owner returns my name, along with the brand's review status.

request: get_decision_owner(decision_class="claims") response excerpts: class: claims owner: Greg Appler brand_status: approval: human_reviewed
the pattern: assess: score the brand inventory codify: build the reviewed source serve: expose the source to agents and workflows produce: draft and adapt from the source check: compare output to the source review: a person reviews each draft route: send questions the reviewer cannot settle to the decision owner update: return approved corrections to the source

Why it matters

Brand copies in prompts, custom assistants, and agency decks can age differently.

Serving one source lets people update the brand material that automations and agents use for both drafting and checking.

MCP handles the connection. The brand work is deciding what the source contains, how to serve it, and who answers questions the source leaves open.
